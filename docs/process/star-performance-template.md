# STAR 变更记录模板

每个功能、缺陷或性能 PR 在描述和评论中保留一份可复现记录。不得填写
没有基准证据的“提升百分比”。

```text
Situation（情境）：线上/测试环境的现象、数据规模、基线版本。
Task（任务）：要解决的用户影响或工程指标，以及约束。
Action（行动）：算法、数据结构、并发模型、缓存/队列/索引和代码位置。
Result（结果）：正确性证据；P50/P95/P99、吞吐、错误率、资源占用的前后对比。

基准命令：
环境：CPU/内存/JDK/中间件版本：
数据规模：
基线：
改动后：
结论与遗留风险：
回滚方式：
```

Bug 修复同样使用 STAR：Result 必须包含回归测试名称和修复前后行为差异。
