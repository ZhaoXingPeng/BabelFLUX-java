BabelFlux 开发与提交规范
版本：v1.0（2026-09）

本文与根目录 CONTRIBUTING.md、docs/standards/architecture.md 共同组成当前规范。若历史文档与本文冲突，以 CONTRIBUTING.md 和本文为准。

一、工作流

1. 一个 Issue 定义一个可验收问题；一个 PR 只解决一个 Issue。
2. 从最新 main 创建短生命周期分支，完成实现、测试和证据后再提交 PR。
3. main 只接受可运行、可审阅的合并结果；不直接向 main 推送。
4. 大功能按协议、实现、测试、运行验证拆成可独立回滚的 PR，不在最后集中导入代码。
5. 本阶段 CI 不作为开发阻塞条件；完整项目收口时再启用 CI 门禁，但本地测试与真实启动验证仍是每个实现 PR 的必需项。

二、分支与标题

分支名使用小写 ASCII 和短横线：

- `feat/<topic>`：新增用户可见能力
- `fix/<topic>`：修复可复现缺陷
- `refactor/<topic>`：不改变外部行为的结构调整
- `test/<topic>`：测试覆盖或测试工具
- `docs/<topic>`：文档和规范
- `chore/<topic>`：依赖、脚本和维护
- `perf/<topic>`：有基准证据的性能改进

Issue、PR 和 commit 标题统一使用中文，并使用 gitemoji + Conventional Commits：

`<emoji> <type>(<scope>): <动词开头的简短摘要>`

示例：

- `🐛 fix(search): 限制多实例报告索引重复处理`
- `✨ feat(provider): 接入百炼实时音频网关`
- `🧪 test(search): 覆盖索引租约恢复边界`
- `📚 docs(process): 统一 Issue 与 PR 证据规范`

摘要建议不超过 72 个字符；scope 使用稳定模块名，如 `api`、`search`、`messaging`、`provider`。

三、Issue 模板

```text
## Situation（情境）
现象、影响、版本、数据规模和可复现输入。

## Task（任务）
目标行为、约束、验收条件和不在范围内的内容。

## Evidence（证据）
日志、请求/响应、失败测试名称或运行命令；不得包含密钥和隐私数据。
```

四、PR 描述模板

```text
## 关联
Closes #<issue> 或说明无需关联 Issue 的原因。

## Situation（情境）
基线版本、现象、影响和数据规模。

## Task（任务）
本 PR 的单一目标、验收条件和范围边界。

## Action（行动）
关键代码位置、数据结构/算法、并发模型、中间件语义、兼容性与安全取舍。

## Result（结果）
功能行为、回归测试、真实启动/接口验证、性能数据和未覆盖风险。

## 验证命令
列出可复制的命令、环境、输入规模和结果，不使用“应该”“预计”等推测。

## 发布与回滚
配置、数据库迁移、中间件开关、前后端兼容性和单 commit 回滚方式。
```

五、PR 评论与性能记录

每次重要实验单独追加评论，不覆盖历史结论：

```text
实验：假设、基线、命令和方法。
环境：CPU/内存/JDK/数据库/中间件版本。
数据规模：记录数、消息数、并发数、音频时长等。
结果：P50/P95/P99、吞吐、错误率、资源占用或明确的通过/失败。
结论：保留、放弃或下一步；未测量的指标写“未测量”。
```

性能数字必须来自本次改动前后可重放的实测；没有基准不得填写提升百分比。Bug 修复的 Result 必须写修复前后差异和回归测试名。真实中间件未启动时必须明确标注 skipped，不能把 mock/H2 结果写成 MySQL、Redis、RabbitMQ 或 Elasticsearch 实测。

六、Commit 规则

1. 一个 commit 保持可编译、可测试、可回滚；正文说明背景、方案和验证。
2. 不提交 `.env`、API key、token、Cookie、私钥、真实音频或用户隐私文本。
3. 代码和命令标识使用 ASCII；中文文档统一 UTF-8，提交前检查乱码和换行风格。
4. 提交前运行 `mvn -B test`、前端类型检查/测试，以及本 PR 影响到的真实服务启动验证。

七、SSH 提交流程

GitHub remote 必须使用 SSH：

```bash
git remote set-url origin git@github.com:ZhaoXingPeng/BabelFLUX-java.git
ssh -T git@github.com
git push -u origin <branch>
```

若 `ssh -T` 失败，先修复本机 SSH agent/key 配置；不得退回 HTTPS token 推送。PR 创建和审查在 GitHub 完成，合并前确认标题、描述、评论证据、测试结果和回滚步骤完整。

八、合并检查清单

- [ ] Issue 与 PR 一一对应，标题格式统一且无乱码。
- [ ] 变更只覆盖一个可验收目标，前后端协议变更有契约测试。
- [ ] `mvn -B test` 与受影响客户端检查通过。
- [ ] 真实启动和 HTTP/WebSocket 验证结果已记录；未启动的中间件明确 skipped。
- [ ] STAR 结果包含可复现证据，不夸大性能或模型质量。
- [ ] 配置、迁移、依赖和回滚说明完整，敏感信息已清理。
