## 对项目经历的有效要求

综合官方入口的技术岗位分类，以及各家公开 Java 后端岗位长期稳定的能力项，
BabelFlux 不应只写“调用大模型”。项目需要形成可演示、可测量、可回滚的工程闭环：

1. **Java/Spring 基础**：Java 21、Spring Boot、REST、WebSocket、参数校验、统一异常和单元/契约测试。
2. **数据与存储**：MySQL 事务和索引设计；Redis 缓存、分布式会话、幂等键与 TTL；Elasticsearch 报告检索。
3. **分布式与稳定性**：RabbitMQ 异步削峰、重试/死信、有限队列背压、超时、降级和优雅关闭。
4. **计算机基础**：哈希索引、有界滑动窗口、队列和状态机；说明时间/空间复杂度；理解 JVM、线程池、网络与 I/O。
5. **生产工程**：结构化日志、指标、链路 requestId、配置与密钥隔离、Docker、压测和故障演练。
6. **AI 服务工程**：百炼 DashScope HTTP/实时 WS 适配器、模型路由、限流、成本/时延/质量指标和供应商错误映射。

## 本项目的简历化交付标准

每个真实功能或缺陷修复才创建 PR，并在 PR 中记录：

- 业务影响和数据规模，而不是笼统描述“优化”；
- 关键设计取舍、数据结构/复杂度、并发和失败边界；
- 基线与改动后的 P50/P95/P99、吞吐、错误率和资源占用；
- 回归测试、部署/回滚步骤；
- 用 Situation、Task、Action、Result 组织叙述。

尚未测量的指标写“待测”，不虚构百分比。CI 按项目约定在完整后端功能完成后
作为最后一步统一收口，当前阶段不以 CI 状态替代功能验证。

## 结论

当前最有价值的下一步不是继续堆砌中间件，而是完成协议 parity 和 DashScope 实时
链路，随后用真实音频基准测量 WebSocket 首包延迟、端到端字幕延迟、纠偏 P95 和
资源占用；这些结果才能形成可信的后端/全栈面试项目故事。
